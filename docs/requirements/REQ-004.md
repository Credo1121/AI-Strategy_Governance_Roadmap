# REQ-004 — Interaktive GitHub-Pages-Demonstration

Status: Ready, Revision 1. Quelle: Nutzeranweisung vom 12.10.2026.

## Problem und Nutzen

Die bisherige GitHub-Pages-Ausgabe zeigt Repository-Inhalte beziehungsweise eine Anleitung, aber keine laufende Anwendung. GitHub Pages stellt ausschließlich statische Dateien bereit und kann den Node.js-/SQLite-Service nicht ausführen. Der Nutzer benötigt eine direkt aufrufbare, interaktive Web-Demonstration zur Sichtung der Ergebnisse.

## Scope

- Die bestehende Next.js-Anwendung als statischen Export unter dem Repository-Unterpfad `/AI-Strategy_Governance_Roadmap/` ausliefern.
- Katalog und zwei synthetische Demoakten ohne Backend im Browser bereitstellen.
- Erstellen, Bearbeiten, Speichern, Neuladen und Markdown-Export im Pages-Modus ermöglichen.
- Änderungen ausschließlich im lokalen Browser-Speicher halten und den Modus sichtbar kennzeichnen.
- GitHub-Actions-Workflow für Build, Tests, Pages-Artefakt und Deployment auf `main`.
- Lokalen Node.js-/SQLite-Modus unverändert als Entwicklungs- und Integrationsmodus erhalten.

## Nicht-Scope

Kein serverseitiges Konto, Team-Sharing, zentraler Datenbestand, vertrauliche Kundendaten, SQLite in GitHub Pages, Produktions-SSO oder dauerhafte Sicherung über Browser/Gerät hinweg.

## Akzeptanzkriterien

- AC-01: `STATIC_EXPORT=1 NEXT_PUBLIC_STATIC_DEMO=1 npm run build` erzeugt ohne Serverabhängigkeit ein statisches Pages-Artefakt.
- AC-02: Die Anwendung lädt unter `/AI-Strategy_Governance_Roadmap/` einschließlich CSS und JavaScript und zeigt den Browser-Demomodus sichtbar an.
- AC-03: Katalog und beide synthetischen Ausgangsakten sind verfügbar; Änderungen lassen sich speichern und nach Reload aus `localStorage` wiederherstellen.
- AC-04: Neue synthetische Akte und Markdown-Export funktionieren ohne `/api`-Netzwerkzugriff.
- AC-05: Fehlerhafte oder veraltete Browserdaten werden nicht ungeprüft verwendet; sie fallen auf validierte Ausgangsdaten zurück.
- AC-06: Lokaler API-/SQLite-Modus, Typecheck, Backendtests und normaler Produktionsbuild bleiben funktionsfähig.
- AC-07: GitHub Workflow nutzt Node.js 24, `npm ci`, Typecheck, Tests, statischen Build und die offiziellen Pages-Actions mit minimalen Berechtigungen.
- AC-08: Die öffentliche Pages-URL und der ausgelieferte Commit werden nach dem Push geprüft; wenn Repository-Einstellungen das Deployment blockieren, wird der konkrete externe Schritt benannt.

## Qualitätsgrenze

GitHub Pages ist ein öffentlicher statischer Demonstrationskanal. Browserdaten sind geräte- und profilgebunden und können gelöscht werden. Die Anwendung zeigt ausschließlich synthetische Inhalte; echte Kundendaten bleiben untersagt.
