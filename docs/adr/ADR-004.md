# ADR-004 — Dualer Laufzeitmodus für GitHub Pages

Status: entschieden für REQ-004.

## Entscheidung

Der bestehende lokale Next.js-/Node.js-/SQLite-Modus bleibt die Referenz für API-, Persistenz- und Konflikttests. Für GitHub Pages erzeugt derselbe Frontendcode einen statischen Next.js-Export mit Repository-`basePath`. Ein kleiner Browseradapter beantwortet die bestehenden Katalog- und Aktenoperationen aus validierten synthetischen Daten und `localStorage`. Der Markdown-Export wird im Browser als Blob erzeugt.

Der Pages-Modus wird ausschließlich über Buildvariablen aktiviert und in der Oberfläche sichtbar gekennzeichnet. Der GitHub-Workflow erhält `contents: read`, `pages: write` und `id-token: write`; keine Secrets oder externen Datenbanken.

## Folgen

Die fachliche Oberfläche lässt sich ohne Server direkt begutachten. Daten werden nicht zwischen Nutzern oder Geräten geteilt, besitzen keinen serverseitigen Konfliktschutz und sind kein belastbarer Speicher. Der Adapter bildet nur die für die Demonstration benötigte API-Semantik ab. Vor realer Zusammenarbeit ist ein autorisierter Backendbetrieb mit Authentifizierung, Mandantentrennung, Audit und Backup erforderlich.

Alternative „Node-Backend auf GitHub Pages“ ist technisch nicht möglich. Ein externer Hostinganbieter wäre für eine gemeinsame persistente Anwendung geeignet, ist aber nicht Bestandteil dieses Auftrags.
